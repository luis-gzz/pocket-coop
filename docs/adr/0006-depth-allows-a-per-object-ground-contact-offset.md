# Depth is every world object's bottom edge

ADR-0005 decided a world object's depth was simply its own y, with no per-type anchor, to keep Y-sort configuration-free for future object types. In practice this was visibly wrong: display objects are center-anchored by default, so a world object's own y is its vertical *center*, not where it actually contacts the ground - a chicken had to walk roughly half a sprite-height further down the screen than its feet before it would correctly render in front of a dropping sitting right at them, and a dropping's own center sat noticeably above its own visual bottom too.

We're reversing that call: depth is a world object's **bottom edge**, not its raw y. `YSort.add` now takes an optional `getDepth(object)` function; it defaults to the object's raw y for a call site that doesn't override it, but every current world object supplies one that adds half its own height (a dropping's `HEIGHT / 2`) or its sprite's confirmed bottom-edge offset (the chicken's `GROUND_OFFSET`, pixel-checked against its idle/walk/eat sheets, none of which have transparent padding at the bottom of their frame). This reintroduces the per-type configuration ADR-0005 was trying to avoid, but the rule itself ("depth = bottom edge") is uniform and simple enough that any future world object type just needs to know its own height.
