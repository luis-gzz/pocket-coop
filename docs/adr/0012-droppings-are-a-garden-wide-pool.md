# Droppings become a garden-wide pool, not per-chicken

Until this refactor, a dropping lived entirely inside the chicken that made it: `Gauges.droppings` was a per-instance array, and a chicken's cleanliness target only ever counted its own mess (`#self.droppings`) plus the garden-wide floor egg count, which was already global via Coop. That asymmetry didn't matter with one chicken, but this refactor makes the chickens collection plural-ready, and it forces the question: if two hens share an island, does hen A's dropping count against hen B's cleanliness too?

We chose yes — droppings move out of `Gauges` entirely and into Garden's own state, alongside beds/eggs, which already worked this way. `Gauges:update` now takes a `dirtyItemCount` computed once per frame by Garden (`#droppings + floor egg count`) instead of reading its own private list. The alternative — keeping droppings per-chicken, so two hens standing in the same mess would report different cleanliness scores — was rejected: it doesn't match how a shared coop actually works (one mess is everyone's problem, not just the hen who made it), and it would have left droppings as the one inconsistent case among world objects that are otherwise all garden-wide (beds, eggs, food). The cost is that a chicken's own poop-clock timing (`cyclesSincePoop`, `poopClockAccumulator`, `lastAteAt`) stays a private per-chicken concern — only the resulting dropping record becomes shared — so *whether and when* a hen poops is still entirely her own behavior, only *whose cleanliness it affects* changed.
